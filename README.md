# 西安小吃夜市地图

一个微信小程序：以西安钟楼为中心的地图，用绿色半透明矩形标出小吃摊贩集中区域，点击查看区域信息、评分、摊点与留言。中英双语，面向本地人和来西安旅游的外国游客。

> **开发原则：模块化、小步走。**
> 每次只做一个模块，做完能跑通、能验收，再进下一个。不追求一次写出大而全的小程序。
> 完整需求见 [需求梳理.md](需求梳理.md)。

### 现在能做什么

- 地图上显示绿色半透明矩形，点击弹出详情卡片（提示条、加载中 / 失败 / 无数据几种状态都齐）

- 网页管理后台：密钥登录、区域增删改、地图点两下画框取坐标、一键生成 / 清除示例数据

### 技术结论（全是踩过的坑，别重蹈）

1. **`map` 组件的 `bindpolygontap` 不触发**（基础库 3.17.3 实测）。选中判定不依赖多边形，用点击坐标 + 自己写的矩形命中算法。
2. **点中地图上的地名只发 `poitap`、不发 `tap`**。两个事件都要接，否则卡片会"点不动"。
3. **热重载必须关**，而且要关两处：`project.config.json` 和 `project.private.config.json`（后者优先级更高）。开着会出现"页面 JS 还是旧的"，报"没有这个方法"。
4. **数据库集合的权限一律选最严格那档**（客户端不可读不可写）。小程序从不直连数据库，全部走云函数；云函数以管理员身份访问，不受权限限制。千万别选"所有用户可读"。
5. **云函数有两种事件形状**：`callFunction` 调用时是 `{ action, key }`，被 HTTP 访问服务调用时是 `{ httpMethod, body: "字符串" }`。`cloudfunctions/admin` 里的 `parseEvent` 负责统一。
6. **节流标志遇到页面挂起会卡死**。"等异步回调再解锁"的状态必须有超时兜底，否则页面切走一次就永久失效（星星气泡就吃过这个亏）。
7. **地图没有"经纬度 ↔ 屏幕坐标"的接口**。气泡位置是自己算的：`getRegion` 拿可视范围 + 线性插值。双指缩放时 `regionchange` 不连续触发，要靠定时轮询兜底。
8. **渲染要拆开**。改卡片内容（点星星、点词块）不能顺手重设 `polygons`，否则地图会整个重画一遍，看起来是闪烁。
9. **部署云函数一律选「上传并部署：云端安装依赖」**，不要选「所有文件」，否则云函数找不到模块。
10. **`user` 和 `admin` 云函数不能在控制台的"测试"里跑**：前者没有用户上下文拿不到 openid，后者需要密钥。

### 本机才能用的配置

这两个文件**不进版本库**，换机器要照着同目录的 `.example.js` 重新建：

- `admin/server.config.js` —— 云函数 HTTP 地址
- `admin/map.config.js` —— 腾讯地图 key

云函数的环境变量在云开发控制台设置，同样不进版本库：`admin` 函数的 `ADMIN_KEY`、`zone` 函数的 `ADMIN_OPENIDS`。

## 二、技术选型

| 项目 | 选择 | 理由 |
| --- | --- | --- |
| 小程序框架 | 微信原生小程序 | 只有地图 + 卡片，不需要跨端 |
| 后端 | 微信云开发（云数据库 + 云函数） | 免服务器、免域名备案、成本最低 |
| 地图底图 | 微信原生 `map` 组件 | 不引入第三方 SDK |
| 区域矩形 | `map` 组件的 `polygons` 覆盖物 | 4 个点即矩形，原生支持点击事件 |
| 管理后台 | 静态网页 + 腾讯地图 JS API | 不需要构建工具，部署在云开发静态托管 |
| 管理员登录 | 单密钥，存在云函数环境变量 | 一个人用，不需要账号体系 |

### 三个关键架构决定

1. **数据库不开放前端直写。** 所有写操作（打分、投票、留言）都走云函数。否则任何人都能绕过审核直接写库。
2. **坐标只存两个对角点。** 数据库存东北 `ne` + 西南 `sw`，矩形的 4 个顶点由云函数算出来返回给前端，从根上避免坐标不一致。
3. **双语字段从第一天就带 `_zh` / `_en` 后缀。** 阶段 12 只是补英文内容和加切换按钮，不需要回头改数据结构。

---

### 阶段 1 真机验证结论（重要，后续都按这个来）

在真机上实测得到的事实，避免以后反复踩：

| 能力 | 结论 |
| --- | --- |
| `map` 组件的 `bindpolygontap`（点中多边形） | ❌ **不触发**（基础库 3.17.3 实测，点了无数次都没发过） |
| `map` 组件的 `bindtap`（点地图） | ✅ 正常，且**会回传点击处的经纬度** |
| `map` 组件的 `bindregionchange`（视野变化） | ✅ 正常 |
| `map` 组件的 `bindpoitap`（点中地图 POI） | ✅ 正常 |
| `MapContext.getRegion()`（读当前视野范围） | ✅ 正常 |
| 普通 `view` 浮在地图上显示与点击 | ✅ 正常（同层渲染工作良好） |

**补充结论**：点中地图上的地名（如"钟楼"这类标注）时，地图**只发 `poitap`、不发 `tap`**。如果只监听 `tap`，用户点到地名的那一下会毫无反应，表现为卡片"点不动"。所以两个事件必须都接，并且走同一套坐标命中逻辑。

**由此确定的选中方案**：不依赖多边形事件。用户点地图时拿 `bindtap` 回传的经纬度，用 `utils/geo.js` 里的矩形命中算法自己判断点到了哪个区域。多边形只负责显示，不参与交互。

这个方案比原计划更稳：命中逻辑攥在自己手里，不受地图组件事件支持情况影响，将来换机型或升级基础库也不会失效。

**另一条教训**：热重载（`compileHotReLoad`）必须保持关闭。开着它会出现"WXML 已更新、页面 JS 还是旧的"这种错配，表现为新绑定的方法报"页面没有这个方法"，极难排查。改完代码请**清缓存后重新编译**。

要注意这个开关有**两个地方**：`project.config.json` 和 `project.private.config.json`，后者由开发者工具生成、**优先级更高**。如果只在前者关掉而后者的值是 `true`，热重载依然是开着的。稳妥做法是在开发者工具里「详情 → 本地设置」直接把它勾掉，两个文件就都对了。

**调试约定**：页面左上角面板标题带版本号（如 `B4`），另有一个每秒自增的心跳数字。以后只要看到版本号和心跳，就能立刻确认跑的是不是最新代码。

## 四、通用约定

### 云函数

- 前端统一通过封装好的 `callCloud(name, action, data)` 调用，集中处理 loading、报错提示、超时
- 统一返回格式：成功 `{ ok: true, data: ... }`，失败 `{ ok: false, code: 'XXX', msg: '人话错误信息' }`
- 错误码统一管理，前端按 `code` 决定提示文案或引导登录
- 每个云函数自己从上下文取 `openid`，**永不信任前端传来的身份**

**注意云函数的事件有两种形状。** 同一个函数，被小程序 `callFunction` 调用时收到的是 `{ action, key, ... }`；被「HTTP 访问服务」当网址调用时收到的是 HTTP 那一套 `{ httpMethod, headers, body, isBase64Encoded }`，我们要的数据在 `body` 里、而且是**字符串**。admin 云函数里有一段 `parseEvent` 专门把两种形状统一成第一种。

漏掉这一步的症状非常好认：`event.key` 永远是 `undefined`，于是"密钥怎么输都不对"。修改云函数后**必须重新部署**才会生效。

| code | 含义 | 前端行为 |
| --- | --- | --- |
| `NEED_LOGIN` | 未登录 | 触发登录后自动重试，不打断用户操作 |
| `ALREADY_VOTED` | 已投过票 | 提示"你已经评价过了" |
| `INVALID_PARAM` | 参数不合法 | 提示具体问题（如金额超范围） |
| `FORBIDDEN` | 无权限 | 提示无权限 |
| `NOT_FOUND` | 数据不存在 | 提示内容已下架 |
| `INTERNAL` | 服务端异常 | 通用错误提示 |

### 数据

- 双语字段一律 `_zh` / `_en` 后缀
- 所有集合都带 `created_at`，可编辑的带 `updated_at`
- 摊点删除用软删除 `is_deleted`，不做物理删除，历史投票记录保留
- 统计值（平均星、票数、均价）实时聚合，不存冗余字段
- 唯一性靠云函数先查后写 + 数据库组合唯一索引双保险

**所有集合的权限一律设成最严格的那档**（控制台里通常叫「仅管理端可读写」，判断标准是"客户端既不能读也不能写"）。

原因是这套架构里客户端从来不直接碰数据库：小程序读写全部经过云函数，而云函数以管理员身份访问数据库，不受权限设置限制。所以客户端根本不需要任何直接的数据库权限，给得越少越安全。

特别不要选「所有用户可读，仅创建者可读写」——那意味着任何客户端都能直接读完整个集合，`users` 里的 openid 会成批泄露。

### 界面

- 所有文案走 `i18n` 表，**代码里不出现硬编码中文**
- 主色：体现夜市感的深色底 + 主题绿；矩形和高亮统一用同一个绿，具体色值在阶段 1 定
- 矩形统一：填充绿色半透明、描边同色不透明；普通与选中两个状态只有透明度差异
- 底部卡片用页面内弹出层实现，不用地图原生气泡，避免原生组件层级问题
- 所有提交类操作完成后给明确反馈，并提示"不可修改"的后果

### 阶段 3 · 管理后台 v1：密钥 + 画矩形 + 区域管理

> 拆成两步做：**3a** 先把管道打通并能管理数据，**3b** 再接地图。

### 阶段 6 · 区域星级评分

**目标**：第一个真正的用户提交功能。

**已完成**

**评分模型（四条规则）**

1. **48 小时后才生效**。刚打的分数在 48 小时内不计入推荐度，用户能看到自己的评分，状态是「等待生效中」。
2. **去掉一个最高分和一个最低分**再算平均。只有 1~2 条评分时不去极值，否则会一条不剩。
3. **刷分降权**。48 小时内给满 10 个不同区域打过分的人，判定为刷分：他已有的评分在统计里**只按两成权重**算。
4. **频率上限**。同一个人再想给第 11 个区域打分会被拦下，提示"打分太频繁咯，稍后再试吧"。已有的评分仍可修改。在最后一个评分满 48 小时后，降权自动解除。

管理员的 openid 不受频率限制。把 openid 填进 `zone` 云函数的环境变量 `ADMIN_OPENIDS`（逗号分隔多个）即可；不填就等于没有管理员豁免。

**展示**

- 卡片里的「夜市推荐度」不显示分数，直接给一句态度，格式 `“好评如潮” · 56人评`
  - 分档表在 `miniprogram/utils/rating.js`：好评如潮（≥4.5）／大多好评（≥4.0）／褒贬不一（≥3.0）／差强人意（≥2.0）／缺乏管理（<2.0）
  - 无人评价 → `请为这个夜市打分`
  - **人数不足 10 人** → 灰色，且不给具体人数，写成 `“褒贬不一” · 少于10人评价`
- 卡片里的「你的评分」是用户自己的打分，用星星输入，旁边显示「等待生效中 / 生效中」
- **卡片不再有关闭按钮**，点地图空白处收起
- **打过分的夜市，绿框中心浮一个会晃的星星气泡**，点它可以直接选中该区域（气泡本身不吃点击）

**评分怎么提交**：点星星、点词块都只改本地，**不弹任何确认框**。等卡片被关掉时（点地图空白处、切到别的夜市、离开页面）统一提交。这是一份"草稿"式的交互——填的时候没人打断你，离开时才落库。

**四个维度放在卡片上**：选了星星之后，星星下面出现四行词块（卫生/座位/拥挤/管理，各三个词，只显示词不显示维度名），可以点选。「我的打分」里同样能改。

**气泡为什么能跟着地图走**：地图组件没有"经纬度换算成屏幕坐标"的接口，所以自己算——用 `getRegion` 拿当前可视范围的经纬度边界，再线性插值。`regionchange` 在拖动过程中会连续触发，用"上一次请求还没回来"当节流阀，气泡就能跟手移动，而不是等停下才跳一下。

**「我的 → 我的打分」**

- 列出自己打过的所有夜市，每条显示名称、状态（等待生效中 / 生效中）、可点的星星
- 改分走一次确认弹窗，改完 48 小时**不重新计时**（避免"先随便打一个、生效后再改成想要的"）
- 每条下面有四行词块，对应四个维度，各三个词，只显示词不显示维度名：
  - 卫生：干净整洁 / 还过得去 / 眼不见为净
  - 座位：随便坐 / 得抢座 / 只能带走
  - 拥挤：摩肩接踵 / 有些人气 / 摊主比顾客多
  - 管理：井井有条 / 普普通通 / 乱糟糟的
  - 存储时只存 0 / 1 / 2，不存文字，以后改词或加语言都不影响已有数据

**展示用文字，输入用星星**：上面那行是所有人的汇总，用文字是为了让用户不用自己把"4.2 分"换算成好不好；下面那行是用户自己的操作，用星星点起来最直接。

**为什么分档表独立成文件**：分档口径大概率还要调，集中放在 `utils/rating.js` 一个数组里，改边界值不用翻页面。

**示例数据**：管理后台新增了「生成示例数据 / 清除示例数据」两个按钮，一键造出 6 个夜市和 61 条评分，覆盖"没人评过 / 人数不足（灰） / 好评如潮 / 褒贬不一 / 差强人意 / 缺乏管理"全部状态。所有示例数据带 `is_demo` 标记，清除时只删它们，不碰你自己的数据。

1. 右键 `cloudfunctions/zone` → **上传并部署：云端安装依赖**
2. 右键 `cloudfunctions/admin` → **上传并部署：云端安装依赖**

**验收**：英文模式下没有中文残留（微信平台固定文案除外）；英文缺失的摊点回退显示中文，而不是空白。

### 阶段 13 · 邮件通知

**目标**：有新留言时你能收到通知，不用一直盯后台。

**做什么**

- 在 `admin` 云函数里加发信模块，用邮箱 SMTP 授权码发信到管理员 iCloud 邮箱
- 邮件内容：留言类型、所属区域/摊点、留言内容、提交时间、后台链接
- 触发点：新留言提交、新开发者留言提交
- 发信失败不能让用户提交失败：**异步发送 + 失败只记日志**

**交付物**：提交留言后，邮箱收到通知。

**验收**：故意填错授权码，用户提交依然成功，只在日志里看到发信失败。

**兜底**：如果云函数发信被环境限制，改为后台未读红点 + 每日汇总。

### 阶段 14 · 打磨与提交审核

**目标**：从"能跑"到"能用"。

**做什么**

- 空状态、加载中、错误态统一处理
- 首页地图加载性能、矩形数量增长后的表现
- 隐私协议弹窗与必要的授权说明
- 准备提交审核的材料：
  - 说明留言采用**人工审核机制**，未审核内容不对外展示
  - 说明定位只用于地图跳转、不留存
  - 核对服务类目
- 提交审核，处理驳回意见

**交付物**：审核通过，可以发布。

## 八、附录：阶段 2 部署步骤（需要你操作）

代码已经写好了，但要让它在你的云环境里跑起来，得做四件事。顺序不能颠倒。

### 1. 建数据库集合

开发者工具 → 顶部「云开发」→ 数据库 → 点「+」新建集合，名字**必须正好是** `zones`（全小写）。

权限保持默认的「仅创建者可读写」即可。小程序端从不直连数据库，所有读写都经过云函数，而云函数是以管理员身份访问的，不受这个权限设置影响。这样设置最安全。

### 2. 导入初始数据

两条路，任选一条。**推荐第 2 条**，只有 3 条记录，手工录入最省事。

**路线 A：文件导入**

选中 `zones` 集合 → 点「导入」→ 选择 `seeds/zones.json` → 冲突处理模式选 **insert** → 确定。

注意这个文件的内容是「每行一个 JSON 对象」，扩展名必须是 `.json`——云开发要的就是这个格式，用 `.jsonl` 会被文件选择器拒掉。另外，导入功能会先把文件传到云存储再解析，所以**云存储必须先初始化过**，否则会报 `No available bucket`。去「云开发 → 存储」页面看一眼，如果提示创建存储桶就先创建。

**路线 B：手工录入（推荐）**

在 `zones` 集合里点「添加记录」，把 `seeds/zones.json` 里的一行粘进 JSON 编辑模式，保存。重复三次。

**字段说明**

| 字段 | 含义 |
| --- | --- |
| `name_zh` / `name_en` | 中英文名称，`name_en` 可以留空 |
| `business_hours` | 营业时间，纯文本，怎么写都行 |
| `ne` | 矩形**东北角**的经纬度（`latitude` 纬度、`longitude` 经度） |
| `sw` | 矩形**西南角**的经纬度 |
| `sort_order` | 排序，数字越小越靠前，只影响内部顺序，不影响用户看到的任何排名 |
| `is_visible` | `true` 上架 / `false` 下架，也可以整个字段不写（默认视为上架） |

### 3. 部署云函数

在开发者工具左侧的文件树里找到 `cloudfunctions/zone` 文件夹 → 右键 → **上传并部署：云端安装依赖**。

第一次会比较慢，因为要在云端安装 `wx-server-sdk`。看到「上传成功」就好了。

注意必须选「云端安装依赖」这一项，不要选「上传并部署：所有文件」——那样会把本地空空的 `node_modules` 传上去，云函数会报找不到模块。

### 4. 验证

重新编译小程序 → 点右上角「调试」展开面板 → 看「数据源」那一行。

显示「云端 · 3 个区域」就通了。然后去数据库改一条记录的坐标（比如把纬度加个 0.001），下拉刷新小程序，地图上的绿框应该跟着挪位置——这就证明数据真的来自数据库了。

## 九、附录：阶段 3a 部署步骤（需要你操作）

目标是让浏览器里的管理后台能控制小程序上的绿框。一共四步。

### 1. 给云函数设置密钥

云开发控制台 → 云函数 → 找到 `admin` → 配置（或「版本与配置」）→ 环境变量 → 新增一条：

| 变量名 | 值 |
| --- | --- |
| `ADMIN_KEY` | 你自己定的一串密钥 |

密钥随便定，但别用 `123456` 这种。它同时就是后台的登录密码，记牢，代码里不会出现它。

如果 `admin` 函数这时候还不存在（还没部署过），先做第 2 步，部署完再回来设置。

### 2. 部署云函数

右键 `cloudfunctions/admin` → **上传并部署：云端安装依赖**。

同样地，不要选「上传并部署：所有文件」。

### 3. 给云函数开一个网址（HTTP 访问服务）

云开发控制台 → 找到「HTTP 访问服务」（有的版本叫「HTTP 触发」或「云函数 URL 化」）→ 新建一条路径映射：

| 项 | 填什么 |
| --- | --- |
| 路径 | `/admin` |
| 方法 | POST |
| 目标函数 | `admin` |

建好后控制台会给你一个完整网址，形如：

```
https://xxxxxxxx.service.tcloudbase.com/admin
```

复制它。

### 4. 填进本地配置并启动

打开 `admin/server.config.js`，把网址填进 `cloudApiUrl`：

```js
module.exports = {
  cloudApiUrl: 'https://xxxxxxxx.service.tcloudbase.com/admin',
  port: 8080
}
```

然后在项目根目录跑：

```
node admin/server.js
```

看到 `Admin server is running.` 就对了。浏览器打开 http://127.0.0.1:8080 ，输入你刚才设的密钥。

### 验证

能进到区域列表、看到数据库里那 3 个区域，就说明整条链路通了。然后试着改一个区域的中文名称并保存，回小程序重新编译，看名字变了没有。

如果卡住，看浏览器里的红色提示条，以及跑 `node admin/server.js` 那个窗口的输出——错误信息基本都会直接说明是哪儿的问题（地址填错、密钥不对、函数没部署）。

## 十、附录：阶段 5 部署步骤（需要你操作）

三步，和阶段 2 那套流程一样。

### 1. 建 users 集合

云开发控制台 → 数据库 → 新建集合，名字**必须正好是** `users`。权限保持默认。

建议顺手加一个索引防重复：集合 → 索引管理 → 新建索引 → 字段填 `openid`，类型选**唯一**。

加了之后，即使出现极端并发，同一个人的第二条记录也插不进去。不加也能跑（代码里已经做了先查后写 + 前端请求去重），只是少一层保险。

### 2. 部署云函数

右键 `cloudfunctions/user` → **上传并部署：云端安装依赖**。

### 3. 验证

重新编译小程序 → 点地图右上角「我的」→ 页面上应该出现一个绿色圆圈和「夜市迷XXXX」。

注意：`user` 云函数只能用小程序调用，**不能在云开发控制台的"测试"里跑**。因为控制台测试没有用户上下文，拿不到 openid，会直接返回"没有拿到用户身份"。这不是 bug。

然后去 `users` 集合里看，应该有且只有一条记录，里面有 `display_name_zh`、`display_name_en`、`login_count`。

反复进出「我的」页面几次，再看集合——如果出现了第二条记录，说明去重没生效，告诉我。

### 排错：一直提示「密钥不正确」

先确认不是这里的问题：**改了云函数代码之后必须重新部署**，云端跑的永远是上次部署的那份。

想跳过网页、直接验云函数，用这条命令（把地址和密钥换成你自己的）：

```powershell
Invoke-WebRequest -Uri 'https://xxxxxxxx.service.tcloudbase.com/admin' `
  -Method POST -ContentType 'application/json' `
  -Body '{"action":"ping","key":"960209"}' -UseBasicParsing |
  Select-Object -ExpandProperty Content
```

期望看到 `{"ok":true,"data":{"pong":true,...}}`。根据实际返回可以判断是哪一层出了问题：

| 返回内容 | 说明 |
| --- | --- |
| `{"ok":true,...}` | 云函数没问题，问题在本地服务器或配置文件 |
| `{"ok":false,"code":"FORBIDDEN"}` | 云函数没读到密钥——多半是部署的还是旧版本 |
| `{"ok":false,"code":"NO_KEY"}` | 请求体没被解析出来，同样是云函数版本问题 |
| `{"ok":false,"code":"CONFIG_MISSING"}` | 环境变量 `ADMIN_KEY` 没设上，或者设在了别的函数上 |
| 一堆 HTML 或 404 | HTTP 访问服务的路径映射没配好 |
